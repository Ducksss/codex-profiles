codex-profiles is a free, open-source macOS menu bar app and dependency-free Bash CLI for managing Codex profiles. Check Codex CLI quota and open named ChatGPT windows with separate local state on macOS; CLI commands also support Linux.

(01) Separation

Orbits, not overlaps.

Every profile selects its own CODEX_HOME. Named profiles on macOS also open a ChatGPT window with its own Electron data across Chat, Work and Codex. Nothing is copied between them.

(02) Menu bar and terminal

Mission control
in the menu bar.

The menu bar app and the CLI show the same profiles, quota and workspaces. Each numbered marker points to the same thing in both.

  1. 01

    Profiles

    Each profile leads its own group in its own colour and symbol, with its workspaces beneath it. Click a row to open it in ChatGPT, or ⌘-click to open it in Terminal. Different names stay open side by side.

    codex-profile appearance shares the look with the shell prompt and Raycast. codex-profile app work or codex-profile cli work opens the profile from the CLI.

  2. 02

    Codex quota

    Each profile shows its tightest Codex window as a figure and a ring that turns orange or red when it runs low. A low row names a healthier profile, and the lowest share can sit beside the menu bar icon. The app never switches profiles or accounts for you.

    codex-profile usage prints every window with its reset time.

  3. 03

    Workspaces

    Bind project folders to a profile and pin the ones you use most. Search from the keyboard, press ⌘1–9 to open a visible row, or turn on ⌃⌥⌘P to open the menu from any app.

    codex-profile workspace list shows the same bindings.

Build it from a source checkout on macOS 13 or newer with make menu-app. It includes codex-profile and uses the official Codex CLI for Terminal launches, sign-in and quota. There is no signed download yet. Follow the build and quota guide.

(04) Safety

Zero contact with
your credentials.

It keeps local state apart and stays out of your credentials. It is open source, so you can read every line it runs.

00auth.json tokens read or copied
00ChatGPT cookies read
00App bundles cloned or re-signed
00Profile switches made for you

+ It does

  • +Select a separate CODEX_HOME for each profile
  • +Give each named ChatGPT window its own Electron data
  • +Open the original, signed ChatGPT app
/!\

Local-state separation is not an account, OS or server-side security boundary. SSH keys, keychains and other credentials stay shared by your macOS user. For strict separation, use separate OS users.

Security model ↗

Security boundary

codex-profiles sets environment variables and creates private Codex and Electron-state directories. It does not claim VM, container, separate macOS account, or verified account-identity isolation. Read the security model and privacy boundaries.

Validation

The repository uses make check as one deterministic syntax, behavior, packaging, release, documentation, and shell-lint gate.

Machine-readable docs

Use the plain-text reference and agent setup guide for supported commands and limitations. Subscribe to releases for published updates.

What is codex-profiles?

codex-profiles is a free, open-source macOS menu bar app and Bash CLI for managing Codex profiles. It opens named ChatGPT windows with separate local state on macOS and supports Codex CLI profiles on macOS and Linux. It is community-maintained and not affiliated with OpenAI.

Can I use multiple Codex accounts with codex-profiles?

Yes. Each profile is its own CODEX_HOME with its own sign-in, so you can sign a different Codex account into each one, for example with codex-profile login work, and choose the profile whenever you start Codex. Unlike tools that swap auth.json into ~/.codex, choosing a profile never copies credentials. codex-profiles does not verify which account a profile uses, and local-state separation is not an account, OS or server-side security boundary.

Is codex-profiles the same as the Codex CLI --profile option?

No. Codex's own --profile option selects a named configuration inside one Codex home: from Codex 0.134.0 a profile-name.config.toml file layered over config.toml, and before that a [profiles.profile-name] table in config.toml. Either way, sign-in, sessions and history stay shared. A codex-profiles profile selects a whole separate CODEX_HOME with its own sign-in, sessions and logs. Codex's --profile still works inside each one, for example codex-profile cli work --profile review.

Why use separate CODEX_HOME directories?

Separate CODEX_HOME directories keep Codex auth, sessions, caches, logs, and local state separated by profile. Configuration and plugins also stay separate unless you explicitly link the documented configuration allowlist with init --share-with.

How does Desktop separation work?

A named app launch selects separate Electron state for the whole ChatGPT window and a matching CODEX_HOME for Codex. The boundary applies across Chat, Work, and Codex, but account identity remains unverified.

What does app default do?

After the default profile is initialized, app default uses ~/.codex and preserves the stock ChatGPT Desktop session without a custom Electron user-data directory.

Does codex-profiles verify that CLI and Desktop use the same account?

No. CLI and Desktop sessions can be authenticated independently, and codex-profiles does not inspect account identifiers or credentials to compare them.

Does codex-profiles copy auth tokens?

No. codex-profiles does not read, copy, print, parse, upload, compare, or migrate authentication tokens or ChatGPT cookies.

Which platforms does codex-profiles support?

CLI-oriented commands are tested on macOS and Linux, while ChatGPT Desktop launching is available on macOS.

How do I install codex-profiles?

Install from npm with npm install -g codex-profile or from Homebrew with brew install Ducksss/tap/codex-profile.

Can multiple named ChatGPT windows run at once?

Yes. Different names use separate local Electron state and can run side by side, while app default keeps the ordinary stock ChatGPT session.

Is there a menu-bar app for macOS?

Yes. On macOS 13 or newer, an optional native menu-bar app built from a source checkout with make menu-app opens profiles and bound projects in ChatGPT or Terminal and shows each profile's remaining Codex CLI quota. It includes codex-profile but still needs the official Codex CLI.

How do I check Codex usage limits for each profile?

Run codex-profile usage. It prints each profile's remaining Codex CLI quota for every reported window, such as the 5-hour and 7-day limits, with reset times, and codex-profile usage --json work returns one profile as JSON. The menu bar app shows each profile's tightest window as a figure and a ring. Readings come from the official Codex app-server without reading credentials or sending inference requests. ChatGPT may use a different account.

Does codex-profiles switch accounts automatically when quota runs low?

No. It never switches profiles or accounts for you. When a profile's tightest window is at 25% or less, the menu bar app highlights it with its reset time, or names a fresh profile with at least half of the same window left. You choose which profile to open.

Can an AI assistant tell me how to run codex-profiles?

Yes. The repository's agent.md is the public installation and setup guide, and llms.txt is the plain-text product reference. Ask your assistant to install codex-profile, initialize work, authenticate with codex-profile login work, and launch codex-profile cli work. AGENTS.md is for repository contributors.

Why does fork fail with rollout path must be in Codex home directory?

Current Codex Desktop resolves the rollout path before checking that it stays under CODEX_HOME. A sessions/ or state_5.sqlite symlink from a named home into another home makes that check fail, so fork and side chats break. A shared state_5.sqlite also breaks archive and delete, which restrict rollout paths to sessions/ and mention that directory in the error. init --share-with never creates those links. Do not symlink the session store. Sharing chats across people means one real Desktop CODEX_HOME. Separate ChatGPT logins then require selecting that account's auth.json; the account chip follows CODEX_HOME auth.json, not Electron user-data alone. This tool does not copy auth.json.
